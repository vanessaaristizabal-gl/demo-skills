Certification concept at each step

  1. 2
    The coordinator owns coverage.

    If something is missing even though the subagents did their job, the root cause is how the coordinator split and assigned the work. It picks subagents per case instead of following a fixed pipeline.

  2. 3
    Parallel work with labeled context.

    Notes are independent, so they run at the same time and each extractor receives only its own. Every item travels with its source (note and date), like the Source column in the backlog.

  3. 4
    Structured errors and informed retries.

    A failure goes back to the extractor with the specific error, not a bare "try again". An error is never swallowed silently.

  4. 5
    Restrict with permissions, not prompts.

    The Drafter is never given the create-ticket tool (allowedTools). If you don't want it to use the hammer, don't hand it the hammer.

  5. 6
    Human oversight before an external effect.

    Creating a ticket changes someone else's system. Nothing is written until a person approves, and the person can correct the draft.

  6. 7
    Idempotency and traceability.

    The idempotency key stops the same item from being created twice. The audit log makes it possible to rebuild who proposed and who approved.
